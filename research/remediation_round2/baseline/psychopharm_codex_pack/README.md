# Калькулятор психофармакотерапии — пакет для Codex

**Назначение:** запустить поиск опубликованных алгоритмов и подготовить их к оцифровке для хакатонного MVP. Это не готовый медицинский калькулятор и не база проверенных дозировок.

Подготовлено: **4 октября 2026 года**. Язык работы и результатов — русский.

## Как начать

1. Распакуйте архив и откройте папку `psychopharm_codex_pack` как рабочую папку в Codex. При переносе в существующий репозиторий согласуйте содержимое с уже имеющимся `AGENTS.md`, не перезаписывайте его вслепую.
2. Отправьте Codex текст из `START_PROMPT.txt`.
3. Результаты поиска должны появиться в `research/`. Не нужно заранее выбирать все вопросы анкеты: их набор должен следовать из найденных правил.

`AGENTS.md` размещён в корне пакета как проектная инструкция. Механизм проектных инструкций описан в официальной документации OpenAI: https://developers.openai.com/codex/guides/agents-md/ (проверено 04.10.2026; адрес перенаправляет на официальную страницу ChatGPT Learn).

Наличие файлов само по себе не предоставляет Codex доступ к интернету или закрытым базам. Если поиск недоступен, агент должен явно сообщить об этом, а не представлять знания по памяти как выполненный поиск.

## Содержимое

| Файл | Для чего нужен |
|---|---|
| `AGENTS.md` | Постоянные правила проекта: что создаём и чего не изобретаем |
| `PROJECT_BRIEF.md` | Зафиксированные требования пользователя и границы MVP |
| `RESEARCH_PROMPT.md` | Основное задание на поиск, извлечение и проверку алгоритмов |
| `SEARCH_PLAN.md` | Поисковые направления, запросы и правила работы с источниками |
| `SOURCE_SEEDS.md` | Стартовые источники с честно обозначенным статусом доступа |
| `RULE_TEMPLATE.yaml` | Пустой шаблон карточки правила; не исполняемый медицинский алгоритм |
| `ACCEPTANCE.md` | Проверка, что результат действительно соответствует задаче |
| `START_PROMPT.txt` | Короткий текст для запуска работы в Codex |

## Главный принцип

**Опубликованное правило → необходимые для него входы → воспроизводимый расчёт → доза/диапазон и схема → ссылка на источник.**

Не наоборот: сначала придумать 50 вопросов и собственную формулу, а затем искать ей обоснование.

Порядок работы: найти правила → проверить применимость → описать их в таблицах и карточках → подготовить техническое задание на реализацию. Разработка интерфейса и вычислительного модуля — следующая задача, а не подмена поиска.

## Что считать результатом первого запуска

Карта диагнозов и источников, конкретные правила старта/титрования/отмены/перехода, минимальные вопросы для каждой ветки, карточки правил с источниками, перечень пробелов и план реализуемого MVP. Основной сценарий — врач выбрал препарат; дополнительный — до трёх вариантов по рекомендациям с дозовыми схемами.

Доказательность исходного правила, точность его переноса в программу и клиническая проверка нового продукта — разные вещи. Этот пакет не объявляет будущий продукт валидированным или зарегистрированным.
